# Architecture

_Updated: 2026-10-29_

## Overview

NativePerformanceKit is a React Native library (Turbo Native Module + Codegen) exposing process memory and FPS snapshots with a start/stop monitoring lifecycle. See `specs/spec.md` (WHAT) and `specs/plan.md` (HOW).

**Current reality:** Phase 3. `getSnapshot()` returns a real memory snapshot on both platforms (`fps` null); `isMonitoring()` returns false; `startMonitoring`/`stopMonitoring` reject with `E_UNIMPLEMENTED` until Phase 4. The example shows the memory snapshot. Everything marked `(planned)` is not built.

## Components

Built:
- Memory collectors: Android `MemoryCollector` reports total PSS (KB to bytes, `Long`); iOS `PKMemoryCollector` reports `phys_footprint` (bytes). Timestamp = Unix epoch ms. Unavailable/non-positive reads throw and the module rejects `E_MEMORY_UNAVAILABLE`. Readers and clock are injected for tests. `getSnapshot` is exported from `src/index.tsx` as a pass-through.
- TurboModule spec (`src/NativePerformanceKit.ts`): `startMonitoring(intervalMs)`, `stopMonitoring()`, `isMonitoring()`, `getSnapshot(): Promise<NativeSnapshot>` with `fps: number | null` (Codegen accepts the nullable). A compile-time check in `src/__tests__/index.test.tsx` keeps `NativeSnapshot` assignable to the public `PerformanceSnapshot`.
- Android/iOS stubs: `isMonitoring` returns false; start/stop/getSnapshot reject `E_UNIMPLEMENTED`.
- iOS registration: works at runtime with the template as-is (verified on simulator) despite the empty `moduleMapping`.

Template baseline:
- Codegen spec: `src/NativePerformanceKit.ts` exports `TurboModuleRegistry.getEnforcing<Spec>('PerformanceKit')`. `codegenConfig` = `{ name: "PerformanceKitSpec", type: "modules", jsSrcsDir: "src", android.javaPackageName: "com.performancekit" }`.
- Android: `PerformanceKitModule` extends the generated abstract `NativePerformanceKitSpec`; `PerformanceKitPackage` extends `BaseReactPackage` and reports `isTurboModule = true`. Registered via autolinking (no manual MainApplication edits).
- iOS: `PerformanceKit` (NSObject) conforms to the generated `NativePerformanceKitSpec` protocol, returns `NativePerformanceKitSpecJSI` from `getTurboModule:`, `+moduleName` = "PerformanceKit". Pod `PerformanceKit` via `install_modules_dependencies`. Swift is not offered by the template for turbo modules (`kotlin-objc` only); Swift collectors, if used, are called from the `.mm` module.
- Example: Expo dev-build app resolving the library from source through the `react-native-performance-kit-source` export condition.

Planned (per spec section 7):
- TypeScript layer (planned): remaining public API (`startMonitoring`, `stopMonitoring`, `getSnapshot`), validation, error normalization, optional hook.
- Android collectors (planned): Choreographer FPS and the shared session (memory collector is built).
- iOS collectors (planned): CADisplayLink FPS and the shared session (memory collector is built).

## Data / control flow (planned)

JS API -> TurboModule -> single shared native session (memory sampler + frame observer) -> snapshot `{timestamp, memoryUsageBytes, fps|null}` returned to JS. Stop/invalidate releases timers and frame callbacks.

## Key decisions and constraints

- Library generated with `create-react-native-library@0.64.0 --type turbo-module --languages kotlin-objc --example expo --tools eslint jest`; its conventions are the source of truth for registration.
- Example lives at the repo root (`example/`), library under `packages/`; Yarn workspaces link them.
- One shared native monitoring session, no per-consumer collectors.
- No telemetry, no network, metrics stay local.
- Expo Go cannot load custom native code: the example needs a development build.

## Build / test commands

From the repo root (needs `corepack enable`):
- `yarn` (install), `yarn typecheck`, `yarn lint`, `yarn test`, `yarn prepare` (bob build to `packages/react-native-performance-kit/lib`).
- `yarn example ios|android|start`.

From `example/`:
- `npx tsc --noEmit`, `npx expo lint`, `npx expo-doctor`.
- `npx expo prebuild --platform android` then `cd android && ./gradlew assembleDebug`.
- `npx expo prebuild --platform ios` then `yarn build:ios` (xcodebuild, iphonesimulator).
